## **وحدة تشكيل الفرق والإحالات – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** تشكيل الفرق والإحالات  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة تشكيل الفرق والإحالات  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

توثق هذه الوثيقة متطلبات وحدة تشكيل الفرق والإحالات، وهي وحدة أساسية في نظام إدارة التقاضي، تتيح للمشرف على الإدارة تكوين فريق عمل لكل قضية بناءً على معايير محددة، مع إمكانية تعديل الفريق خلال مراحل القضية، وتسجيل كل عملية إحالة أو تعديل في سجل رسمي.

يدعم النظام إدخال الدارس، المشاركين، الممثل، المعتمد، والبدائل، مع مراقبة الأعباء الحالية والخبرة السابقة لضمان التوازن، كما يُتيح إنشاء إحالات رسمية وتوثيقها داخل النظام، بما يشمل تغييرات الفريق، تكليف الأدوار، أو تمرير المهام الداخلية.

### **3\. الأهداف**

1. تنظيم عملية تشكيل الفريق القضائي لكل قضية على أساس واضح وموثّق.  
2. دعم تعيين الأعضاء حسب الخبرة، التخصص، والحمل الوظيفي.  
3. توثيق كل عملية إحالة أو تعديل في سجل زمني رسمي.  
4. دعم تعيين بدائل للأدوار الحساسة مثل الممثل والدارس.  
5. تمكين المشرف من إعادة تشكيل الفريق عند الحاجة.  
6. ضمان مرونة التشكيل مع الحفاظ على الحوكمة.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| المشرف على الإدارة | مسؤول التشكيل الأولي والتعديلات | تعيين – تعديل – اعتماد – إلغاء |
| النظام | يحتفظ بالسجل الزمني ويراقب التعارضات | يمنع التكرار – يسجل كل إجراء |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: تشكيل الفريق عند تسجيل القضية**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | إمكانية تعيين دارس، مشاركين، معتمد، ممثل، وبدائل داخل كل قضية |
| F-1.2 | إدخال معلومات كل عضو ودوره بدقة |
| F-1.3 | دعم وجود أكثر من مشارك لنفس القضية |
| F-1.4 | دعم وجود بدائل لكل شخص بشكل عام بالنظام مع امكانية عمل استثناءات عند تشكيل فريق العمل  |
| F-1.5 | دعم تعيين نفس الموظف في دورين مختلفين داخل نفس ملف القضية ونفس المرحلة |

**ثانيًا: اختيار الأعضاء بناءً على معايير مرنة**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | عرض الحمل الوظيفي الحالي لكل عضو عند التعيين |
| F-2.2 | عرض السجل السابق للعضو داخل نفس نوع القضية |
| F-2.3 | إمكانية تحديد تفضيلات لكل نوع قضية مسبقًا (مثلاً: قضايا تجارية ↔ دارسين معينين) |

**ثالثًا: الإحالة والتعديل خلال القضية**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | دعم تغيير أحد الأعضاء أثناء سير القضية (استبدال، إلغاء، إضافة) |
| F-3.2 | تسجيل سبب التعديل وتاريخه والجهة المنفّذة (اختياري عند الحاجة) |
| F-3.3 | إرسال إشعار للأعضاء المتأثرين بالتعديل |

**رابعًا: تعيين البدائل المؤقتة**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | إمكانية تعيين بديل افتراضي لدارس أو ممثل |
| F-4.2 | تفعيل البديل تلقائيًا في حالات الإجازة أو الغياب |
| F-4.3 | تسجيل زمن التفعيل وفترة التغطية في السجل الرسمي |

**خامسًا: سجل التشكيل والإحالات**

| الكود | المتطلب |
| ----: | ----: |
| F-5.1 | سجل زمني مفصّل يوضح كل إجراء متعلق بالفريق |
| F-5.2 | إمكانية تصدير سجل التشكيل للمراجعة أو التحليل |
| F-5.3 | عرض التشكيل المعتمد الحالي والتشكيلات السابقة ان وجدت لكل قضية ولكل مرحلة بشكل واضح |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |
| NFR-1 | تكامل كامل مع إدارة دورة القضية ولوحة المتابعة |
| NFR-2 | دعم عرض الحمل الوظيفي بشكل لحظي أثناء التعيين |
| NFR-3 | سجل التشكيل غير قابل للتعديل بعد اعتماده |
| NFR-4 | تجربة استخدام بسيطة للمشرف عند تكوين الفريق |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: تشكيل فريق أولي لقضية جديدة**

* المستخدم: المشرف على الإدارة  
* النتيجة: الفريق يُسجل داخل القضية، وتبدأ المهام وفق الأدوار المحددة

**UC-2: تعديل ممثل أثناء سير القضية**

* المستخدم: المشرف على الإدارة  
* النتيجة: العضو الجديد يُفعل والقديم يُسجل كمنسحب، مع إشعار الجميع

**UC-3: تفعيل بديل تلقائيًا أثناء إجازة**

* المستخدم: النظام  
* النتيجة: تفعيل صلاحيات البديل للفترة المحددة

### **8\. القيود والافتراضات**

**الافتراضات:**

* النظام يحتوي على قاعدة بيانات شاملة لجميع أعضاء المكتب مع أدوارهم السابقة.  
* النظام مدمج مع سجل الإجازات لتفعيل البدائل تلقائيًا.
