## **وحدة الإشعارات العامة – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** الإشعارات العامة  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة الإشعارات العامة  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

تهدف هذه الوثيقة إلى تحليل وحدة الإشعارات العامة داخل نظام إدارة التقاضي، والتي تُعد مكونًا حيويًا لضمان التنبيه الفوري للمستخدمين المعنيين بكل حدث أو إجراء مرتبط بالقضية أو المعاملة أو المهام.

وتغطي الوحدة إشعارات المهام، الجلسات، المدد النظامية، المشاركات الخارجية، المخرجات، التعديلات، والردود المتوقعة، وتُسهم في رفع الالتزام المؤسسي وتفادي التأخير.

### **3\. الأهداف**

1. تنبيه المستخدمين تلقائيًا عند وقوع حدث يستدعي انتباههم.  
2. تفعيل نظام ذكي للإشعارات يراعي طبيعة الإجراء ودور المستخدم.  
3. دعم التذكير بالمهل النظامية والمواعيد الحرجة.  
4. توثيق جميع الإشعارات في سجل رسمي قابل للمراجعة.  
5. إمكانية تخصيص من يستلم كل نوع من الإشعارات حسب إعدادات الإدارة.  
6. دعم الإشعارات التلقائية واليدوية في آن واحد.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| مشرف الإدارة | يضبط إعدادات الإشعارات ويخصص المستلمين لكل نوع | التحكم الكامل في توزيع الإشعارات وتفعيلها |
| أعضاء الفريق (دارس – مشارك – معتمد – ممثل...) | يتلقون الإشعارات حسب الدور والمهام | لا يملكون تعديل الإعدادات، فقط استلام الإشعار |
| رئيس المكتب | يمكنه استلام نسخة من الإشعارات الحرجة (اختياري) | تفعيل خاص لإشعارات طارئة أو ذات أثر إداري |
| النظام | مصدر الإشعار الآلي | توليد الإشعارات وتتبع حالتها |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: أنواع الإشعارات المدعومة**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | إشعار بوجود مهمة جديدة (إعداد مذكرة – حضور جلسة...) |
| F-1.2 | إشعار بتغيّر حالة قضية أو تعديل الفريق |
| F-1.3 | إشعار بمشاركة خارجية موجهة للمستخدم |
| F-1.4 | إشعار بقرب انتهاء مدة نظامية (اعتراض، تنفيذ...) |
| F-1.5 | إشعار برد من الخصم أو صدور حكم جديد |
| F-1.6 | إشعار برد وارد من الطرف الخارجي على مشاركة |
| F-1.7 | إشعار داخلي عند التمرير داخل الفريق (مثل ملاحظات المعتمد أو المدير) |
| F-1.8 | إشعارات عند تقرير جلسة، استلام حكم (مع نسخة الحكم) \-وهو مختلف عن صدور الحكم-، انتهاء فترة اعتراض، حلول موعد تسليم الحكم، انتهاء مدة الشطب. |

**ثانيًا: وسائل الإشعار**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | إشعار داخل النظام (Notification Center) |
| F-2.2 | إشعار عبر البريد الإلكتروني الداخلي |
| F-2.3 | إمكانية تفعيل واحدة أو أكثر لكل نوع من الإشعارات |

**ثالثًا: التخصيص والتحكم**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | تخصيص مستلمي كل نوع من الإشعارات من إعدادات الإدارة |
| F-3.2 | تمكين وتعطيل أنواع محددة من الإشعارات حسب الرغبة |
| F-3.3 | إرسال إشعار يدوي عند الحاجة من قبل رئيس المكتب أو المشرف |

**رابعًا: سجل الإشعارات**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | تسجيل كل إشعار برقم المعاملة أو القضية أو المشاركة المرتبطة |
| F-4.2 | توثيق الجهة المرسِلة والمستلم وتاريخ الإرسال وحالته (تم التسليم، فشل...) |
| F-4.3 | دعم تصدير سجل الإشعارات لتقرير إداري عند الحاجة |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |
| NFR-1 | وصول الإشعار خلال ثانيتين من حدوث الحدث المرتبط |
| NFR-2 | واجهة مستخدم مخصصة للإشعارات مع خاصية "غير مقروء" |
| NFR-3 | دعم تعدد الوسائط (نصوص \+ روابط \+ مرفقات إن لزم) |
| NFR-4 | حماية خصوصية الإشعار حسب صلاحية المستخدم |
| NFR-5 | إمكانية تهيئة كل إشعار من الإعدادات المركزية |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: إشعار بوجود جلسة قادمة**

* المستخدم: ممثل قانوني  
* المدخلات: موعد الجلسة – اسم القضية  
* النتيجة: إشعار فوري يوضح الموعد واسم القضية

**UC-2: إشعار بمهلة نظامية تنتهي قريبًا**

* المستخدم: دارس / معتمد  
* المدخلات: تاريخ بدء المهلة – عدد الأيام المتبقية  
* النتيجة: تنبيه تلقائي يوضح قرب انتهاء المهلة

**UC-3: إشعار برد على مشاركة خارجية**

* المستخدم: دارس / المشارك في القضية  
* المدخلات: رقم المشاركة – محتوى الرد  
* النتيجة: إشعار داخلي \+ إشعار بالبريد إذا فُعل

**UC-4: إرسال تذكير يدوي**

* المستخدم: مشرف أو رئيس المكتب  
* المدخلات: نوع الإجراء – المستخدم المستهدف  
* النتيجة: إشعار مباشر للمستلم عبر الوسيلة المحددة


### **8\. القيود والافتراضات**

**القيود:**

* لا يُسمح بتعديل سجل الإشعارات بعد إرساله.  
* بعض الإشعارات تعتمد على إدخال بيانات صحيحة (مثل: تاريخ تبليغ – موعد جلسة).

**الافتراضات:**

* كل مستخدم مسجل بنظام البريد الداخلي.  
* إعدادات النظام تم ضبطها مسبقًا عند بدء التشغيل.
