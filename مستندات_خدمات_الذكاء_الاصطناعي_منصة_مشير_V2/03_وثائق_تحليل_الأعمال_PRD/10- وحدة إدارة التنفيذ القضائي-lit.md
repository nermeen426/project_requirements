## **وحدة إدارة التنفيذ القضائي – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** إدارة التنفيذ القضائي  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة إدارة التنفيذ القضائي  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

تعالج هذه الوثيقة متطلبات وحدة التنفيذ القضائي داخل نظام التقاضي، والتي تُعنى بمتابعة تنفيذ الأحكام القضائية، سواء كانت لصالح الديوان أو ضده، بما يشمل إجراءات الرفع، المراجعة، الردود، المنازعات، والتوثيق الكامل لكافة مراحل التنفيذ.

وتُمثل هذه الوحدة امتدادًا طبيعيًا للقضية، وتُستخدم عند صدور حكم قابل للتنفيذ، أو عند ورود إنذار تنفيذ موجه ضد الديوان، **مع إمكانية فتح مسار تنفيذ مستقل غير مرتبط بحكم، عند الحاجة.**

### **3\. الأهداف**

1. تنظيم ومتابعة جميع مراحل التنفيذ القضائي بشكل مؤسسي.  
2. توثيق الخطوات والإجراءات المتعلقة بطلبات التنفيذ.  
3. إدارة منازعات التنفيذ عند حدوثها كمسار دعوى مستقل داخل النظام.  
4. ربط مراحل التنفيذ بالقضية الأم وسجلها الزمني.  
5. دعم إعداد صحيفة التنفيذ وتجهيز المرفقات والبيانات المطلوبة.  
6. تسجيل ردود المحكمة والمراسلات التبادلية ضمن سجل رسمي.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| سكرتير الإدارة | تجهيز مسودة التنفيذ وترشيح الفريق | فتح الملف – تمريره – متابعة المراسلات |
| مشرف الإدارة | اعتماد الفريق والإحالة | تحديد الأعضاء – مراقبة التقدم |
| دارس التنفيذ | إعداد الصحيفة والردود | تجهيز البيانات – تحميل المستندات |
| ممثل التنفيذ | متابعة الطلب مع المحكمة ورفع المستندات | الرفع – تسجيل المستجدات |
| النظام | توثيق الإجراء الزمني وتحليل الحالة | ربط التنفيذ بالقضية الأم أو فتح مسار مستقل |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: فتح ملف تنفيذ جديد**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | فتح سجل تنفيذ جديد مرتبط بحكم نهائي أو مسار مستقل |
| F-1.2 | إدخال رقم الحكم، نوعه، تاريخه، وصف موجز |
| F-1.3 | إمكانية الربط بالقضية الأم تلقائيًا أو يدويًا |

**ثانيًا: إعداد صحيفة التنفيذ**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | نموذج مرن لإعداد صحيفة التنفيذ قابل للتخصيص |
| F-2.2 | رفع المستندات الداعمة (الحكم – البيانات النظامية – الوثائق...) |
| F-2.3 | معاينة الصحيفة قبل إرسالها – دعم الإخراج المناسب للمنصة القضائية المستهدفة |

**ثالثًا: رفع الطلب ومتابعة المحكمة**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | تسجيل تفاصيل رفع الطلب للمحكمة (تاريخ، منصة، رقم الطلب...) |
| F-3.2 | توثيق أي مراسلات أو ردود ترد من المحكمة ضمن السجل |
| F-3.3 | إدخال التحديثات المرحلية (مقبول – ناقص – قيد المراجعة – منازعة...) |

**رابعًا: منازعات التنفيذ**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | فتح مسار منازعة تنفيذ مثل مسار الدعوى عند اللزوم داخل التنفيذ نفسه |
| F-4.2 | إدخال تفاصيل المنازعة، وتسجيل الردود والإجراءات |
| F-4.3 | ربط نتيجة المنازعة بالقضية الرئيسية وتنفيذ الحكم عند الحسم |

**خامسًا: المذكرة الختامية والإغلاق**

| الكود | المتطلب |
| ----: | ----: |
| F-5.1 | توليد مذكرة ختامية توضح ما تم في التنفيذ، وتوقيتها |
| F-5.2 | تمرير المذكرة للمشرف للمراجعة والاعتماد |
| F-5.3 | إغلاق سجل التنفيذ وربطه بالأرشفة في نهاية القضية |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |
| NFR-1 | قابلية فتح أكثر من تنفيذ لنفس القضية (إذا استدعى الأمر) |
| NFR-2 | دعم إخراج الصحيفة والمراسلات بصيغ متعددة |
| NFR-3 | سرعة في تسجيل الردود والمعالجة أقل من 3 ثوانٍ |
| NFR-4 | تأمين تام للمرفقات والمراسلات المرتبطة بالتنفيذ |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: فتح مسار تنفيذ حكم نهائي**

* المستخدم: سكرتير الإدارة  
* الخطوات: اختيار القضية → تحديد الحكم → فتح سجل تنفيذ  
* النتيجة: ملف تنفيذ جاهز للتكليف

**UC-2: إعداد صحيفة التنفيذ**

* المستخدم: دارس التنفيذ  
* الخطوات: فتح النموذج → تعبئة البيانات → رفع المستندات  
* النتيجة: صحيفة قابلة للإرسال للمحكمة

**UC-3: رفع الطلب ومتابعة المحكمة**

* المستخدم: ممثل  
* الخطوات: إدخال رقم الطلب على منصة التنفيذ → تحديث الحالة  
* النتيجة: تتبع الإجراء داخل النظام

**UC-4: فتح منازعة تنفيذ**

* المستخدم: فريق عمل قضية التنفيذ  
* المدخلات: رد المحكمة أو اعتراض الخصم  
* النتيجة: فتح مسار منازعة يتم متابعته بشكل مستقل

**UC-5: إغلاق التنفيذ وإعداد مذكرة ختامية**

* المستخدم: سكرتير الإدارة  
* الخطوات: مراجعة السجل → إدخال ملخص التنفيذ  
* النتيجة: إغلاق المسار وربطه بسجل القضية

### **8\. القيود والافتراضات**

**القيود:**

* لا يُسمح بتعديل بيانات التنفيذ بعد رفعه للمحكمة.  
* لا يُفتح تنفيذ جديد مرتبط بنفس الحكم إلا عند صدور قرار جديد.

**الافتراضات:**

* منصة التنفيذ القضائية قابلة للتكامل مستقبلًا.  
* يوجد نموذج موحد معتمد لصياغة صحيفة التنفيذ.  
* النموذج قابل للتخصيص والتعديل بناء على المنصة المستهدفة.
