## **وحدة ضبط المدد والإشعارات النظامية – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** ضبط المدد والإشعارات النظامية  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة ضبط المدد الزمنية والإشعارات  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

تُعنى هذه الوثيقة بوحدة ضبط المدد الزمنية والإشعارات، وهي مكوّن محوري في نظام إدارة التقاضي، تُستخدم لإدارة جميع المدد المرتبطة بالقضايا، سواءً كانت مدد نظامية صادرة عن الجهة القضائية (مثل مدة الاعتراض، تقديم مذكرة...) أو مدد تنظيمية داخلية تحددها الإدارة (مثل مهلة إعداد مذكرة أو مراجعة داخلية).

تتكامل الوحدة مع وحدات الجلسات، المذكرات، التنفيذ، وتُستخدم أيضًا في توليد إشعارات ذكية تنبه المستخدمين عند اقتراب أو تجاوز المدة.

### **3\. الأهداف**

1. تسجيل وتتبع جميع المدد المرتبطة بالقضية تلقائيًا أو يدويًا.  
2. التمييز بين المدد النظامية (قضائية) والتنظيمية (داخلية).  
3. إصدار إشعارات استباقية حسب نوع المدة ودور المستخدم.  
4. دعم احتساب المهلة بدقة مع مراعاة العطل الرسمية.  
5. ربط المدة بالإجراء المطلوب مثل إعداد رد أو تقديم اعتراض.  
6. ضمان عدم ضياع مهل نظامية تؤثر على نتيجة القضية.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| المشرف على الإدارة | يحدّد المدد التنظيمية ويفعّل الاستثناءات | إضافة – تعديل – إلغاء – مراقبة |
| سكرتير الإدارة أو الممثل | يُدخل المدد النظامية عند استلام تبليغ أو حكم | إدخال – ربط بالإجراء – متابعة |
| أعضاء الفريق | يتلقون الإشعارات ويتابعون المهام المرتبطة بالمدة | عرض – تنفيذ – تحديث الحالة |
| النظام | يحتسب المدة تلقائيًا ويرسل الإشعارات | توليد – تتبع – تسجيل حالة الاستجابة |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: أنواع المدد**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | تصنيف المدة كنظامية (صادرة عن المحكمة) أو تنظيمية (إدارية) |
| F-1.2 | تحديد إن كانت المدة تؤثر على حالة القضية أم لا |
| F-1.3 | تمييز المدد التي تُحتسب بناءً على تاريخ التبليغ |
| F-1.4 | امكانية تحديد شرط التفعيل لكل مدة |
| F-1.5 | امكانية تحديد طريقة احتساب كل مدة مثل بناء على تاريخ التبليغ أو تاريخ استلام الحكم الخ |
| F-1.6 | إمكانية وضع شروط مخصصة لكل مدة تحكم طريقة احتسابها  |
| F-1.7 | **التمييز** بين نوعين أساسيين من المدد؛  **الأول: مدد لأداء المهمة خلالها (قبل انتهائها)**، مثل المدة إلى تاريخ الجلسة، ومدة انتهاء الاعتراض إذا كان الحكم لغير صالح الديوان، ومدة الرد على الاعتراض أمام العليا.   **والثاني: مدد انتظار (تنشأ المهمة بعد انتهائها)**، مثل مدة استلام الحكم، وفترة الاعتراض إذا كان لصالح الديوان، والشطب.   **وانعكاس التفريق بين النوعين** على المهام، وعلى المؤشرات ولوحة المتابعة، وعلى الإشعارات سواء في وقت الإشعار أو في تحديد الأشخاص المستلمين. |

**ثانيًا: إدارة المدد داخل النظام**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | إدخال المدة يدويًا أو توليدها تلقائيًا حسب نوع القضية |
| F-2.2 | تعديل المدة لاحقًا بموافقة المشرف على الإدارة |
| F-2.3 | ربط المدة بالإجراء المرتبط (مثل رد – حضور – تقديم...) |

**ثالثًا: احتساب المدة**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | احتساب الأيام المتبقية تلقائيًا مع مراعاة العطل الرسمية |
| F-3.2 | عرض تاريخ الانتهاء المتوقع بدقة |
| F-3.3 | تفعيل عدّ تنازلي في لوحة متابعة المهام للمستخدم المعني |

**رابعًا: الإشعارات المرتبطة بالمدد**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | إشعار فوري عند تسجيل المدة للمستخدم المسؤول عنها |
| F-4.2 | تفعيل إشعارات تذكير (آليًا أو يدويًا) عند اقتراب الانتهاء |
| F-4.3 | إشعار خاص عند انتهاء المدة دون استجابة (مهلة منتهية) |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |
| NFR-1 | دقة احتساب تاريخ الانتهاء مع مراعاة الإجازات القضائية الرسمية |
| NFR-2 | عرض الإشعارات في مركز الإشعارات والبريد الداخلي معًا |
| NFR-3 | عدم إمكانية حذف المدة بعد تسجيلها، بل يتم تعديلها بسجل واضح |
| NFR-4 | ربط كل مدة مباشرة بسجل الإجراءات داخل القضية |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: إدخال مدة اعتراض على حكم ابتدائي**

* المستخدم: الممثل  
* النتيجة: النظام يحتسب المهلة، يفعّل الإشعارات، ويربطها بمذكرة الرد

**UC-2: إشعار باقتراب نهاية مهلة تنظيمية لإعداد مذكرة**

* المستخدم: دارس  
* النتيجة: إشعار داخل النظام \+ عدّ تنازلي يظهر في لوحة المتابعة

**UC-3: تعديل المدة بسبب عطلة رسمية أو استثناء**

* المستخدم: المشرف على الإدارة  
* النتيجة: تحديث تاريخ الانتهاء، مع تسجيل السبب

### **8\. القيود والافتراضات**

**القيود:**

* لا يمكن حذف المدة بعد إنشائها إلا لمشرف الإدارة أو من له الصلاحية.  
* لا يُحتسب يوم التبليغ ضمن المدة، ويُراعى نظام العطلات الرسمي.  
* إذا صادف أخر يوم في المهلة يوم عطله يرحل لأول يوم عمل.

**الافتراضات:**

* النظام يحتوي على تقويم قضائي محدث دوريا.  
* كل مدة مرتبطة بمهمة قابلة للتنفيذ أو المراقبة.
