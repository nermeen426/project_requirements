## **وحدة الذكاء الاصطناعي في دعم القضايا – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** الذكاء الاصطناعي في دعم القضايا  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة الذكاء الاصطناعي القضائي  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

تعالج هذه الوثيقة دور وحدة الذكاء الاصطناعي في نظام إدارة التقاضي، بوصفها أداة مساعدة لتحسين جودة التحليل القانوني، تسريع العمل، وتقديم توصيات غير ملزمة تدعم أعضاء الفريق القضائي في أداء مهامهم، دون التدخل في الصلاحيات الرسمية أو اتخاذ القرار بدلًا عن الإنسان.

يتم تفعيل الذكاء الاصطناعي ضمن سياقات محددة تشمل تحليل المذكرات، اقتراح الردود، استباق التأخير، وتحليل أسباب الأحكام، مع احترام صلاحيات كل مستخدم.

### **3\. الأهداف**

1. دعم الفريق القانوني باقتراحات ذكية دون التأثير على القرار النهائي.  
2. تحليل المذكرات والمستندات تلقائيًا لتحديد النقاط الجوهرية.  
3. اقتراح تصنيفات القضايا والكلمات المفتاحية.  
4. المساعدة في توليد مسودات أولية للمذكرات عند الطلب.  
5. تقديم مؤشرات استباقية للتأخير أو الازدواج.  
6. دعم تحليل الأسباب المحتملة للأحكام ضد الديوان.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| المستخدم (دارس – معتمد – مشرف...) | يتلقى مخرجات الذكاء الاصطناعي حسب صلاحياته | مشاهدة – قبول – تجاهل – تعديل |
| النظام | مشغّل نموذج الذكاء الاصطناعي | يُولّد المقترحات – يُسجل استخدامها |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: دعم إعداد المذكرات**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | توليد مسودة أولية بناءً على نقاط مدخلة أو مذكرة خصم |
| F-1.2 | اقتراح ترتيب منطقي للمحتوى القانوني |
| F-1.3 | التنبيه عند وجود تضارب أو تكرار داخل النص |
| F-1.4 | استجلاب القضايا السابقة المشابهة والمذكرات والصحائف السابقة المشابهة. |

**ثانيًا: تحليل المذكرات الواردة**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | تحليل مذكرات الخصم تلقائيًا وتلخيص النقاط الجوهرية |
| F-2.2 | تمييز المواضيع المتكررة أو العبارات النظامية ذات الصلة |
| F-2.3 | ربط النقاط الجوهرية بالقواعد النظامية أو السوابق (إن توفرت) |

**ثالثًا: اقتراح التصنيفات**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | اقتراح التصنيف الموضوعي للقضية تلقائيًا |
| F-3.2 | اقتراح كلمات مفتاحية استنادًا إلى نصوص القضية |
| F-3.3 | إمكانية تعديل أو تجاهل المقترحات يدويًا |

**رابعًا: المراقبة الاستباقية**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | تنبيه المستخدم باحتمالية التأخير في المهام الحساسة |
| F-4.2 | اقتراح توزيع بديل للمهام إذا لاحظ الذكاء ضغطًا على عضو معين |
| F-4.3 | عرض مؤشرات احتمالية ازدواج في الردود أو المهام داخل الفريق |

**خامسًا: تحليل نتائج الأحكام**

| الكود | المتطلب |
| ----: | ----: |
| F-5.1 | تحليل الأحكام الصادرة ضد الديوان واقتراح أسباب الرفض أو الضعف المحتمل |
| F-5.2 | تقديم توصيات لتفادي الأخطاء المتكررة في المذكرات |
| F-5.3 | تصدير تقارير تحليلية قابلة للمراجعة الإدارية |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |
| NFR-1 | لا يتم عرض أي مخرجات إلا حسب صلاحية المستخدم |
| NFR-2 | دعم الإخفاء الكامل للمقترحات في حال رغبة المستخدم |
| NFR-3 | إمكانية تفعيل أو تعطيل وظائف معينة من الإعدادات العامة |
| NFR-4 | جميع المخرجات غير ملزمة وتُعامل كمساعد ذكي فقط |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: طلب مسودة رد**

* المستخدم: دارس  
* المدخلات: مذكرة الخصم  
* النتيجة: الذكاء الاصطناعي يقترح مسودة مبدأية قابلة للتحرير

**UC-2: تحليل مذكرة خصم**

* المستخدم: مشارك  
* النتيجة: عرض نقاط جوهرية وتمييز الموضوعات المتكررة

**UC-3: تصنيف آلي للقضية**

* المستخدم: النظام  
* النتيجة: عرض التصنيف المقترح على المستخدم للمراجعة

**UC-4: تحليل حكم مرفوض**

* المستخدم: مشرف أو مدير  
* النتيجة: تقرير ذكي يعرض العوامل المحتملة لرفض القضية

### **8\. القيود والافتراضات**

**القيود:**

* لا يتم تعديل أي شيء في القضية تلقائيًا بناءً على توصية الذكاء الاصطناعي.  
* المخرجات لا تُعتمد رسميًا إلا إذا أقرّها المستخدم البشري.

**الافتراضات:**

* النماذج المستخدمة تم تدريبها على بيانات قانونية ذات صلة بالديوان.  
* المخرجات تُخزن ضمن سجل منفصل كمساعدات غير ملزمة.
