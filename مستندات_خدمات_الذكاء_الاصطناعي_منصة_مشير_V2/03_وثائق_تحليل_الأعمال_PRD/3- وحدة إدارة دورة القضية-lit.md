## **وحدة إدارة دورة القضية – نظام إدارة التقاضي**

### **1\. الغلاف**

* **اسم الوحدة:** إدارة دورة القضية  
* **الجهة:** المكتب الفني – ديوان المظالم  
* **عنوان الوثيقة:** تحليل متطلبات وحدة إدارة دورة القضية  
* **التاريخ السابق:** 06-08-2025  
* **الإصدار السابق:** 0.1 – مبدئي  
* **التاريخ الجديد:** 09-09-2025  
* **الإصدار الجديد:** 0.2 – نهائي

### **2\. المقدمة**

توثّق هذه الوثيقة متطلبات وحدة إدارة دورة القضية، وهي الوحدة المركزية في نظام إدارة التقاضي، والتي تُستخدم لإدارة جميع مراحل القضية الواحدة داخل ملف موحد شامل.

يبدأ هذا الملف من مرحلة ورود القضية (ابتدائية – تنفيذ – اعتراض – استئناف...) ويستمر عبر جميع المراحل اللاحقة حتى الإغلاق والأرشفة، بما يشمل مراحل الإعادة، النقض، أو التنفيذ القضائي.  
 تُربط كل مرحلة فرعية بسجل موحد يحمل تسلسلًا قانونيًا وإجرائيًا واحدًا للقضية.

تتكامل هذه الوحدة مع باقي المكونات التحليلية للنظام، ويُشار إلى أن بعض الأجزاء مثل "إعداد المذكرات"، "التنفيذ القضائي"، و"الجلسات"، يتم إدارتها ضمن وثائق مستقلة، وستُعكس داخليًا في هذه الوحدة، ولكن وفق ما ورد تفصيله في وثائقها الخاصة.

### **3\. الأهداف**

1. إدارة موحدة ودقيقة لجميع مراحل القضية داخل ملف شامل.  
2. دعم تسجيل القضايا الواردة بجميع أنواعها وارتباطها التاريخي بالمراحل السابقة.  
3. تنظيم تسلسل الإجراءات داخل كل مرحلة (رفع – رد – جلسة – حكم).  
4. ضمان توثيق الإجراءات وربط كل مكون بالسجل الزمني الرسمي.  
5. إتاحة الانتقال السلس بين مراحل القضية مع الحفاظ على الترابط.  
6. تكامل كامل مع باقي وحدات النظام دون ازدواج أو تكرار بيانات.

### **4\. الأدوار والصلاحيات**

| الدور | الوصف | الصلاحيات |
| ----: | ----: | ----: |
| المشرف على الإدارة | اعتماد إدخال القضايا الجديدة وتوزيعها | فتح – مراجعة – إغلاق – إحالة |
| سكرتير الإدارة | إنشاء ملف القضية وإدخال البيانات الأساسية | إدخال – تعديل – ربط ملفات – متابعة |
| الدارس | إعداد الإجراءات داخل القضية | متابعة – تنفيذ – طلب إجراءات |
| الممثل | المتابعة الشاملة والتحديث وتمثيل القضية في الجلسات | تحديث – تسجيل حضور |
| النظام | إدارة الملف الموحد وترابط المراحل | تكامل – تحديث تلقائي – سجل زمني |

### **5\. المتطلبات الوظيفية (Functional Requirements)**

**أولًا: فتح القضية وتسجيلها**

| الكود | المتطلب |
| ----: | ----: |
| F-1.1 | تسجيل قضية جديدة واردة للنظام عبر أحد المصادر الرسمية |
| F-1.2 | تحديد نوع المرحلة (ابتدائية، استئناف، عليا، تنفيذ, طلب التماس...) |
| F-1.3 | ربط المرحلة الحالية بأي مراحل سابقة ضمن نفس الملف الموحد |
| F-1.4 | إدخال البيانات الأساسية (أطراف، المحكمة، رقم الدعوى...) |
| F-1.5 | امكانية اضافة حقول مخصصة بملف القضية أو بأي من مكوناته |
| F-1.6 | امكانية منح أو سحب صلاحية الإضافة أو الحذف أو التعديل على كافة الحقول الموجودة بملف القضية |
| F-1.7 | امكانية اضافة دراسات مشابهة أو معاملات مرتبطة بملف القضية |

**ثانيًا: تشكيل فريق العمل وربط الأدوار**

| الكود | المتطلب |
| ----: | ----: |
| F-2.1 | تحديد الدارس، الممثل، المعتمد، المشاركين وربطهم بالقضية |
| F-2.2 | إمكانية إدخال ممثل أو دارس بديل عند الحاجة |
| F-2.3 | تسجيل كل تعديل في الفريق ضمن سجل التغييرات |

**ثالثًا: إدارة الإجراءات داخل المرحلة**

| الكود | المتطلب |
| ----: | ----: |
| F-3.1 | فتح إجراءات مرتبطة (مذكرة – مشاركة – جلسة...) حسب المرحلة |
| F-3.2 | تفعيل المتطلبات الخاصة مثل الرد على الخصم |
| F-3.3 | متابعة تسلسل الخطوات عبر الجدول الزمني للقضية |

**رابعًا: الانتقال بين المراحل**

| الكود | المتطلب |
| ----: | ----: |
| F-4.1 | عند صدور حكم نهائي، يُمكن فتح مرحلة استئناف أو تنفيذ داخل نفس الملف |
| F-4.2 | يدعم النظام تكرار المراحل (مثل إعادة القضية بعد النقض) داخل نفس السجل |
| F-4.3 | كل مرحلة تحتفظ بسياقها لكن مرتبطة زمنيًا بالملف الموحد للقضية |
| F-4.4 | يدعم النظام حالات خاصة بينية بين المراحل الأساسية مثل تقديم طلب التماس او تصحيح ونتيجة هذه الحالات قد تغلق فقط بعدم قبولها او تستدعي اعادة فتح المرحلة السابقة أو الانتقال لمرحلة تالية |

**خامسًا: الإغلاق والأرشفة**

| الكود | المتطلب |
| ----: | ----: |
| F-5.1 | إعداد المذكرة الختامية بعد انتهاء جميع الإجراءات |
| F-5.2 | أرشفة المخرجات والمرفقات النهائية للقضية |
| F-5.3 | تسجيل المرحلة التي انتهت بها القضية رسميًا (حكم نهائي – تنفيذ – شطب...) |
| F-5.4 | إمكانية إعادة فتح القضية بعد غلقها من قبل المشرف على إدارة التقاضي وسكرتير الإدارة ومن له الصلاحية بقرار من المشرف على إدارة التقاضي |

### **6\. المتطلبات غير الوظيفية (Non-Functional Requirements)**

| الكود | المتطلب |
| ----: | ----: |

| NFR-2 | حماية تامة للمراحل المغلقة وعدم السماح بالتعديل عليها إلا بصلاحية |
| NFR-3 | سجل زمني موحد لكل قضية يعرض تسلسل الإجراءات بالتفصيل |

### **7\. بعض حالات الاستخدام (Use Cases)**

**UC-1: تسجيل قضية ابتدائية جديدة**

* المستخدم: سكرتير الإدارة  
* النتيجة: تُنشأ القضية وتُربط بسجل زمني جديد

**UC-2: إضافة مرحلة استئناف داخل نفس الملف**

* المستخدم: المشرف على الإدارة أو السكرتير   
* النتيجة: تُضاف المرحلة الجديدة وتُربط بالمرحلة السابقة تلقائيًا

**UC-3: إغلاق القضية بعد التنفيذ**

* المستخدم: سكرتير الإدارة  
* النتيجة: يُغلق الملف، وتُعد المذكرة الختامية، وتُؤرشف المخرجات

### **8\. القيود والافتراضات**

**القيود:**

* يمكن فتح قضية جديدة بنفس الرقم ولكن يشعر المستخدم بوجود تكرار..  
* الأصل أنه لا يمكن حذف أي مرحلة بعد تسجيل إجراءات داخلها إلا بصلاحية.  
  * صلاحية حذف الوثائق تمنح من المشرف على إدارة التقاضي وغالبا ما تكون للمعتمد.  
  * صلاحية حذف مرحلة بملف القضية أو ملف قضية كامل تمنح من رئيس المكتب وغالبا ما تكون للمشرف على إدارة التقاضي.  
  * طبيعة الحذف:  
    * الحذف يكون حذف نهائي من الأرشيف ويظهر فقط بسجل التدقيق العام بالنظام والخاص لكل مكون حسب نوعه

**الافتراضات:**

* كل مرحلة داخل القضية يمكن ربطها بسابقتها دون تعارض.  
* تم اعتماد نماذج موحدة لتسجيل بيانات القضايا بجميع أنواعها تراجع بمرحلة التصميم.
